# 物流理赔风险评估模型技术路线文档

## 一、项目背景与数据特征

### 1.1 业务背景

物流理赔服务需要将客户提交的索赔申请运单标注为三类风险等级：

- **合理诉求**（类别0）：正常情况下合理的索赔请求
- **诉求偏高**（类别1）：索赔金额偏高，需谨慎处理
- **严重超额**（类别2）：索赔金额严重超过合理范围，需重点审查

### 1.2 数据分布特征

**训练数据分布（train_risked.csv，共11,167条记录）**：

```
类别0（合理诉求）:  9,493 样本 (85.02%)
类别1（诉求偏高）:  1,339 样本 (12.00%)
类别2（严重超额）:    335 样本 ( 2.98%)
```

**数据不平衡分析**：

- **不平衡比例**: 约 28:4:1（类别0:类别1:类别2）
- **主要挑战**：
  1. 类别2样本极少（仅335个），模型难以学习少数类模式
  2. 类别1占比中等，但相对类别0仍处于劣势
  3. 题目要求：严重超额 < 3%，合理诉求 ≥ 85%（符合原始分布）

### 1.3 特征体系（22个特征）

**基础特征（14个）**：

- 线路类型、是否c2c、保价金额、寄件是否内部
- 配送超时时长、妥投到进线时长、索赔金额、新旧程度
- 异常原因_编码、进线渠道_编码、商品类型_编码、进线人身份_编码
- 妥投到进线时长_分桶、生鲜妥投组合类别_编码

**历史聚合特征（8个）**：

- 始发城市_风险特征、目的城市_风险特征
- 寄件人_风险特征、收件人_风险特征
- 始发城市_风险标注均值、目的城市_风险标注均值
- 寄件人_风险标注均值、收件人_风险标注均值

**特征重要性分析（训练结果）**：

```
Top 5 最重要特征:
1. 索赔金额          (25,059.79)
2. 妥投到进线时长      (23,876.87)
3. 寄件人_风险标注均值  (16,045.25)
4. 收件人_风险标注均值  (12,793.97)
5. 保价金额           ( 9,557.50)
```

## 二、技术路线演进过程

### 阶段1：基础尝试 - 简单SMOTE过采样（方案1）

#### 2.1 技术选型

- **采样方法**: SMOTETomek（SMOTE过采样 + Tomek Links欠采样）
- **模型**: LightGBM（默认参数）
- **类别权重**: 使用 `class_weight='balanced'`

#### 2.2 数据表现

```python
原始分布 → SMOTE后分布：
类别0: 9,493 → ~9,500（略微增加）
类别1: 1,339 → ~9,500（大幅增加）
类别2:   335 → ~9,500（大幅增加）
```

#### 2.3 问题与局限

- **验证集 macro-F1**: 0.5089（偏低）
- **类别2召回率**: 仅 19%（严重不足）
- **问题根源**：
  1. SMOTE在少数类样本极少时，生成的合成样本质量不高
  2. 未进行超参数优化，模型性能未充分发挥
  3. 未进行阈值后处理，直接使用 `argmax` 预测导致偏向多数类

### 阶段2：进阶优化 - BorderlineSMOTE + 类别权重（方案2）

#### 2.1 技术选型演进

**为什么选择BorderlineSMOTE？**

- **SMOTE的局限性**：对边界样本的处理不够精确，易生成噪声样本
- **BorderlineSMOTE的优势**：
  - 仅对**边界附近的少数类样本**进行过采样
  - 避免在远离边界的区域生成噪声
  - 更适合类别极度不平衡的场景

**数据驱动决策**：

```python
# 数据分析发现
类别2样本数: 335（仅占总数的2.98%）
# BorderlineSMOTE能更精准地识别这335个样本中哪些是"边界样本"
# 只在边界上生成合成样本，避免噪声
```

#### 2.2 组合策略

- **过采样**: BorderlineSMOTE（kind='borderline-1'，k_neighbors=10）
- **欠采样**: TomekLinks（清理边界上的噪声点）
- **类别权重**: 手动设置 `{0: 1, 1: 3-6, 2: 10-18}`
- **模型**: LightGBM（基础参数）

#### 2.3 采样策略设计

```python
# 采样比例计算（基于多数类数量）
majority_count = y_train.value_counts().max()  # ~7,600

采样策略组合：
- 策略1: {1: 2,278 (0.3x), 2: 759 (0.1x)}     # 保守
- 策略2: {1: 3,037 (0.4x), 2: 1,139 (0.15x)}  # 中等（最终选用）
- 策略3: {1: 3,797 (0.5x), 2: 1,518 (0.2x)}   # 激进
```

**选择中等策略的原因**：

- 类别2样本过少（335个），过度采样可能引入过多噪声
- 0.15倍采样既能增加样本量，又保持数据质量

#### 2.4 性能提升

- **验证集 macro-F1**: 从 0.5089 → 0.52+（略有提升）
- **仍存在的问题**：
  1. 未进行超参数优化，模型潜力未充分挖掘
  2. 直接使用 `argmax` 预测，阈值固定为0.33（三分类），未考虑类别不平衡

#### 3.3 阈值后处理技术（关键创新）

**为什么需要阈值后处理？**

**问题**：直接使用 `np.argmax(proba, axis=1)` 预测时：

```python
# 模型输出概率示例
样本A: [0.85, 0.10, 0.05] → 预测为类别0 ✓
样本B: [0.50, 0.48, 0.02] → 预测为类别0 ✗（实际应为类别1）
# 问题：类别0的概率虽然最大，但仅0.50，并不"强"
```

**解决方案**：使用**单一阈值**判断少数类

```python
# 策略：计算类别1和类别2的概率和
minority_proba_sum = proba[:, 1] + proba[:, 2]

# 如果概率和 > 阈值 → 判定为少数类（1或2）
# 否则 → 判定为多数类（0）

最优阈值 = 0.67  # 在验证集上通过网格搜索确定
```

**阈值优化过程**：

```python
# 阈值搜索范围
th_range = np.arange(0.10, 0.75, 0.01)  # 66个候选值

# 评估指标
score = f1_score(y_test, pred, average='macro')

# 最优阈值
最优阈值: 0.67 → 验证集 macro-F1: 0.5706
```

**为什么选择单一阈值而非双重阈值？**

| 方案                                     | 优点                                                              | 缺点                                                        | 合规性      |
| ---------------------------------------- | ----------------------------------------------------------------- | ----------------------------------------------------------- | ----------- |
| **单一阈值**                       | 493 1. 简单直观`<br>`2. 符合建模规范`<br>`3. 阈值在验证集确定 | 可能无法精确控制分布                                        | ✅ 符合规范 |
| **双重阈值**`<br>`（测试集搜索） | 可以精确控制分布                                                  | 1. 数据泄漏`<br>`2. 过拟合测试集`<br>`3. 不符合建模规范 | ❌ 违规     |

**最终选择**: 单一阈值（0.67），在验证集上确定

## 三、关键技术决策与数据驱动原因

### 3.1 为什么选择BorderlineSMOTE而非标准SMOTE？

**数据证据**：

```
类别2样本数: 335个（仅2.98%）
这些样本中可能存在大量"边界样本"
```

**技术原因**：

1. **边界样本识别**：BorderlineSMOTE能识别哪些少数类样本靠近决策边界
2. **避免噪声**：只在边界上生成合成样本，不在远离边界处生成
3. **效果验证**：交叉验证显示macro-F1提升约2-3%

### 3.2 为什么选择类别权重？

**计算逻辑**：

```python
原始分布: 类别0=9,493, 类别1=1,339, 类别2=335

权重设置思路:
- 类别0: 权重1（基准）
- 类别1: 权重 = 9,493 / 1,339 ≈ 7 → 选择4（保守）
- 类别2: 权重 = 9,493 / 335 ≈ 28 → 选择12（保守）

为什么保守？避免过度惩罚导致多数类性能下降
```

**数据验证**：

- 过高的权重（如1:6:18）导致类别0召回率下降
- 权重{0:1, 1:4, 2:12}在各类别召回率间取得平衡

### 3.3 为什么阈值选择0.67而非默认0.5？

**阈值搜索过程**（在验证集上）：

```python
阈值范围: [0.10, 0.11, ..., 0.74, 0.75]
评估指标: macro-F1

最优阈值: 0.67
对应macro-F1: 0.5706

# 阈值分析
- 阈值 < 0.5: 少数类预测过多（假阳性高）
- 阈值 = 0.5: 默认阈值，未优化
- 阈值 = 0.67: 平衡点，macro-F1最高
- 阈值 > 0.7: 少数类预测过少（假阴性高）
```

**为什么不在测试集上搜索阈值？**

- ❌ **数据泄漏**：在测试集上优化相当于"偷看答案"
- ❌ **过拟合**：测试集分布可能不代表真实场景
- ✅ **规范做法**：阈值在验证集确定，测试集仅用于最终预测

### 3.4 为什么使用RandomizedSearchCV而非GridSearchCV？

**计算复杂度对比**：

```
GridSearchCV:
参数组合数 = 5×4×3×4×4×4×4×3×1 = 46,080种
预估时间 = 46,080 × 5折 × 6秒/折 ≈ 38.4小时

RandomizedSearchCV:
随机采样 = 100种
实际时间 = 100 × 5折 × 4.5秒/折 ≈ 12.5分钟

效率提升: 180倍+
```

**效果对比**：

- GridSearchCV理论上能找到全局最优，但计算成本过高
- RandomizedSearchCV在100次随机采样中能找到**接近最优**的参数组合
- **权衡结果**：选择RandomizedSearchCV（效率与效果的平衡）

## 四、技术路线演进的驱动因素

### 4.1 从SMOTE → BorderlineSMOTE

**驱动因素**：

1. **数据特性**：类别2样本极少（335个），标准SMOTE生成噪声样本
2. **性能瓶颈**：类别2召回率仅19%，需要更精准的采样策略
3. **理论支持**：BorderlineSMOTE专门针对边界样本设计

### 4.2 从固定参数 → 参数搜索

**驱动因素**：

1. **性能上限**：固定参数下macro-F1仅0.52，有优化空间
2. **特征重要性**：发现历史聚合特征（风险标注均值）重要性高，需要优化模型以充分利用
3. **计算资源**：CUDA加速使RandomizedSearchCV在可接受时间内完成

### 4.3 从argmax → 阈值后处理

**驱动因素**：

1. **类别不平衡**：直接argmax导致少数类被忽略
2. **业务需求**：题目要求"严重超额 < 3%"，需要精确控制分布
3. **模型输出特性**：模型输出的是概率，而非类别，需要阈值决策

### 4.4 从双重阈值搜索 → 单一阈值

**驱动因素**：

1. **合规要求**：双重阈值在测试集上搜索属于数据泄漏
2. **建模规范**：阈值必须在验证集上确定
3. **结果稳定性**：单一阈值在验证集上优化，测试集预测更稳定

## 八、总结

### 8.1 核心技术路线

**"BorderlineSMOTE + 类别权重 + 参数搜索 + 阈值后处理"**

### 8.2 关键创新点

1. **精准采样**：BorderlineSMOTE针对边界样本，减少噪声
2. **双重平衡**：采样策略 + 类别权重，双重处理类别不平衡
3. **阈值优化**：在验证集上优化阈值，平衡macro-F1与分布要求
4. **规范预测**：使用训练时确定的阈值，避免数据泄漏

### 8.3 数据驱动的决策过程

- **类别2样本极少（335个）** → 选择BorderlineSMOTE而非标准SMOTE
- **不平衡比例28:4:1** → 设置类别权重{0:1, 1:4, 2:12}
- **验证集macro-F1优化** → 确定最优阈值0.67
- **题目要求（<3%, ≥85%）** → 采用阈值后处理而非直接argmax

### 8.4 符合建模比赛规范

- ✅ 阈值在验证集确定，未接触测试集
- ✅ 历史特征基于训练集计算，测试集仅用于合并
- ✅ 预测流程可复现，结果稳定
